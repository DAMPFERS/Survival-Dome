# Реализация кризисов и зависимостей (по dome_crises.md)

## Быстрый старт

```python
from dome_simulator import create_dome_simulator

sim = create_dome_simulator(seed=3)          # гибридное время, правила, автоматика, кризисы
sim.trigger_crisis("6")                      # №6; псевдонимы: "№6", "n6", "К4", "k4"
sim.start_shift()                            # сброс мира + сценарий 90-минутной смены (раздел 8)
sim.control("cnc_01", "resume", origin="agent")   # команда ИИ-агента
sim.snapshot()                               # телеметрия агента (подмены, заморозки, updated_at)
sim.snapshot(view="truth")                   # истинное состояние
sim.shift_report()                           # метрики смены и отчёты кризисов (раздел 9)
```

Тесты: `python tests/test_runner.py --category crises|deps|shift` (всего 216 тестов).
`tests/reference_agent.py` — эталонный агент: решает все кризисы смены (№19 — ручная оценка).

## Происхождение команд (`origin`)

`agent` — ИИ-агент: не проходит при обрыве связи/заморозке узла, не может выполнять физические
действия Оператора (`operator_controls` в `describe_nodes()`: `switch_path`, `replace_patchcord`,
`inspect_line`, `clean_filter`, `bleed_loop`, `replace_spool`, `set_workstation`, `clean_panels`,
`replace_fan`). `operator` — просьбы, выполненные Оператором (учитываются в метрике отвлечений).
`admin` — по умолчанию, без ограничений. Сервер ставит `agent` для роли team.

## Решения, где документ пришлось уточнить

1. **Прогноз автономности (IL_LOAD_SHED)** считается только при отсутствии внешнего резерва
   (сеть доступна или дизель исправен и топливо GOOD). Иначе в К1 сброс нагрузки случался бы сразу
   на закате при SOC 45 %, а не при 25 %, как в цепочке К1. Следствие: №9 и №46 срабатывают, когда
   резерва нет (в смене — после К1; отдельно — параметр `grid_outage=True`).
2. **IL_OVERCURRENT** (нет в таблице 3.3) добавлен для №49. Уставка линии 1 — 2 А (бюджет рабочего
   места), т.к. ×1,3 от ~1,5 А никогда не достигнет 90 % от 16 А. Настраивается:
   `dome_automation_01.line_current_limits_a`.
3. **К3**: пик — фен/преднагреватель Оператора 90 с (меньше задержки IL_OVERCURRENT). В смене
   перегрузка возникает из-за дерейтинга после №31; без дерейтинга — параметр `inverter_limit_pct`.
4. **К6**: износ картриджа задаётся кризисом (4 %/мин), чтобы цепочка уложилась в смену.
   Забитый фильтр → насос работает без остановки и перегревается → насосная станция FAULT →
   жокей-насос пожаротушения без подпитки → FAULT LOW_PRESSURE (~30 мин без реакции).
5. **№31**: провалом считается и E07 — при отказе вентилятора выход обычно рушится через дерейтинг
   раньше, чем температура дойдёт до 80 °C.
6. **№26**: утечка растёт, пока крутится шпиндель; FeedHold останавливает шпиндель (парковка) —
   это даёт агенту время дождаться осмотра Оператором.
7. **№7/№38**: если канал влажности помечен ненадёжным, автоматика не использует и точку росы,
   вычисленную из него.
8. **IL_SMOKE** работает по зонам: у каждой зоны свой 60-секундный отсчёт. Квитирование события
   отменяет автопуск только для его зоны (№27 и К4 идут одновременно).
9. **Энергобаланс смены**: АКБ 2,56 кВт·ч, старт SOC 64 %, облачность 0,72 → SOC ≈ 45 % на
   закате (проверено: 44,6 %). Аварийное освещение (линия 5) по умолчанию выключено; двери FabLab и
   склада в рабочее время не заперты.
10. **Цикл пожаротушения** — 5 мин (~100 л воды), затем восстановление давления до 10 мин.
11. **Программа Оператора** в виртуальной смене (задания станков, сессии пайки) задаётся сценарием;
    с живым Оператором — `start_shift(params={"simulate_operator": False})`.
12. **№15** (только день 1) реализован виртуально, исход `MANUAL`.
