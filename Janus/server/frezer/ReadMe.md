Режимы запуска

1. Только мониторинг (безопасно, станок не двигается)

python cnc_controller.py 172.31.170.108

Скрипт подключится и раз в 0,25 с будет печатать строку состояния:

Idle     | WPos  145.000    0.000    5.987 | MPos  135.000    0.000   -4.516 | F=0 S=0 |   0.0%

С этого стоит начать. Подвигайте станок из другой программы или рукой (если моторы обесточены) и убедитесь, что координаты меняются. Рабочие координаты (WPos) появятся через 1–3 с, когда GRBL пришлёт WCO. Выход по Ctrl+C.

2. Пробинг Z

python cnc_controller.py 172.31.170.108 --probe --plate 0

Это запускает поиск вниз максимум на 10 мм на F50, затем отъезд на 1 мм и повторное касание на F20. После этого скрипт записывает Z0 в активную СК (обычно G54) и отъезжает на 2 мм вверх. Если касаетесь пластиной, укажите её толщину, например --plate 19.8. Перед первым запуском:

проверьте пробник через ? (как в прошлом ответе про Pn:P);
поставьте фрезу не выше 10 мм над пластиной;
держите руку у аварийной кнопки.

3. Фрезеровка файла

python cnc_controller.py 172.31.170.108 --file board.nc

Флаги можно совмещать: --probe --file board.nc сначала найдёт ноль, потом запустит файл. Ctrl+C во время работы выполняет безопасную остановку: feed hold, затем reset, позиция сохраняется.

Советы для первых тестов

Проверка файла без движения. У GRBL есть режим проверки $C: он разбирает G-code и отвечает ok/error, но станок не двигается. Включите его в своём терминале командой $C и запустите --file. Так вы найдёте ошибки в файле, не рискуя фрезой. Повторная команда $C выключает режим, после неё GRBL делает сброс. Пробинг в этом режиме не работает.

«Сухой» прогон. Шпиндель выключен, рабочий ноль Z задан на 20–30 мм выше заготовки. Станок пройдёт всю траекторию по воздуху.

Подробный лог обмена. В конце файла, в блоке if __name__ == "__main__":, замените level=logging.INFO на level=logging.DEBUG. Тогда будут видны все отправленные строки (>>) и все ответы GRBL (<<). Учтите, что статус приходит 5 раз в секунду, так что лог будет объёмным.
