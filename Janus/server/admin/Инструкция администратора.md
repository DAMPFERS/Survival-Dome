# Админ-панель купола — инструкция

Панель — рабочее место организатора и Оператора купола: вся телеметрия (что видит агент и
истина), кризисы, смена, режимы real/virtual, любые действия узлов и права участников.

> Через панель выполняются **любые** админские команды, включая остановку кризисов и сброс мира.
> Не открывайте её участникам. Команды из панели идут на сервер от имени Оператора
> (`origin = operator`): на них не действуют тихий дроп команд и защита реле от дребезга.

---

## 1. Запуск

Сначала должен работать сервер купола (`server_integrated.py`, порт 8765). Затем на машине
организатора:

```
cd Janus/server/admin
python admin_panel.py                                   # сервер ws://localhost:8765, ключ из data/Hash-keys/admin.txt
python admin_panel.py --server ws://192.168.1.10:8765   # сервер на другой машине
python admin_panel.py --key <ключ> --port 8080          # ключ явно (или переменная DOME_ADMIN_KEY)
```

Откройте в браузере `http://127.0.0.1:8080`. По умолчанию страница доступна только с этого
компьютера; `--host 0.0.0.0` открывает её в сети (например, для планшета Оператора в куполе) —
только в закрытой сети организаторов.

В шапке: время купола, время симуляции и скорость, активная команда, индикатор связи.
«Телеметрия не поступает» — сервер не присылал данные больше 8 с: проверьте сервер и сеть.

## 2. Вкладки

| Вкладка | Что там |
|---|---|
| **Обзор** | Время (пауза, скорость), активная команда, запуск и отчёт смены, энергосистема, метрики смены, линии щитка, интерлоки автоматики, журнал автоматики, активные кризисы |
| **Узлы** | Карточка каждого узла: телеметрия агента и рядом истина, режим real/virtual, выполнение любого действия |
| **Кризисы** | Активные кризисы, каталог с запуском, отчёты, слой подмен и заморозок телеметрии |
| **Окружение** | Истинная погода, воздух зон купола, внешние угрозы, что подменено кризисами, показания реального инвертора, режимы узлов |
| **Доступ** | Права участника (`access_policy.json`): просмотр и правка по узлу |
| **Журнал** | Все запросы панели и ответы сервера — сюда смотреть, если кнопка «ничего не сделала» |

Ошибки сервера появляются всплывающим сообщением внизу и в «Журнале».

## 3. Типовые задачи

### 3.1. Назначить активную команду

**Обзор → Время и смена → «Активная команда» → Назначить.** Ключ выбранной команды получает роль
`team` (телеметрия и управление), остальные — `guest` (только чат `meeting_01`). Подключённые
сессии с изменившейся ролью сервер закрывает — агенты переподключаются тем же ключом.

### 3.2. Запустить 90-минутную смену

**Обзор → «Запуск смены (сценарий 90 минут)»:**

1. Галочка **«Виртуальный Оператор»**: включена — задания станкам, пайку и снятие деталей
   изображает сценарий; **выключите**, если в куполе работает реальный Оператор.
2. Параметры (JSON, необязательно), например `{"start_hour": 13.5}`. Если сервер запущен с
   `TIME_MODE=real`, без `start_hour` смена начнётся с текущего часа купола.
3. **«Сбросить мир и начать смену»** → подтвердить. Мир сбрасывается, текущие кризисы
   останавливаются, кризисы смены идут по таймлайну (см. `../Сценарий на полтора часа.md`).

Метрики идут в карточке «Метрики смены». **«Отчёт смены»** — полный отчёт (исходы кризисов,
штрафы, действия агента) в окне; его можно скопировать.

### 3.3. Запустить отдельный кризис

**Кризисы → Каталог:**

1. Найдите кризис фильтром (по номеру, имени или названию: `17`, `вытяжк`, `k04`).
2. При необходимости впишите **параметры запуска** (JSON) в поле над каталогом — они
   применяются к следующему нажатию «Запуск». Примеры:
   - `{"duration_s": 600}` — длительность (общая для всех кризисов);
   - `{"line": 1}` — линия для №8 и №24;
   - `{"ppm": 3500}` — значение CO₂ для №6;
   - `{"watts": 80}` — мощность фантома для №1.

   Параметры конкретного кризиса — в его коде (`self.p("...")` в
   `simulation/dome_simulator/crises.py` и `cascades.py`). Пустое поле — значения по умолчанию.
3. **«Запуск»**. Кризис с предусловием (станок работает, идёт пайка, печать завершена) сначала
   ждёт его — статус «ожидает»; не дождался за 10 мин — исход `NOT_STARTED`.
4. Остановить — **«Стоп»** в каталоге или **«Остановить»** в «Активных». Подмены показаний
   снимаются, отчёт сохраняется.

Кризис можно запускать и во время смены — он пойдёт параллельно её таймлайну.

**Тот же запуск без панели** (любой WebSocket-клиент с админским ключом):

```json
{"type": "auth", "key": "<админский ключ>"}
{"type": "list_crises"}
{"type": "trigger_crisis", "crisis_name": "n17_fume_extraction_trip", "params": {}}
{"type": "stop_crisis", "crisis_name": "n17_fume_extraction_trip"}
```

`crisis_name` — полное имя (`n06_phantom_co2`) или короткий код: `6`, `№6`, `n6`, `k4`, `к4`.

### 3.4. Следить за кризисом и оценивать

- **Активные** — сколько идёт, статус, время реакции агента, последние заметки.
- **Отчёты кризисов** — исход (`RESOLVED` / `FAILED` / `EXPIRED` / `MANUAL` / `NOT_STARTED`),
  реакция, заметки, штрафы, действия Оператора.
- **Слой телеметрии** — какие показания сейчас подменены для агента и каким кризисом.
- **Узлы** — подменённые значения подсвечены, рядом подпись «истина: …».

### 3.5. Действия Оператора и ручное управление

**Узлы → карточка узла → список действий → значение → «Выполнить».** Под полем — подсказка
формата значения. Значок 👷 — физическое действие Оператора (агент его выполнить не может):

| Действие | Узел | Когда |
|---|---|---|
| `clean_filter` | `fume_extraction_01` | Оператор прочистил фильтр вытяжки (№17) |
| `inspect_line` (значение — номер линии) | `smart_panel_01` | Осмотр кабеля линии (№26 — линия 4) |
| `switch_path` (`RESERVE`) | `network_link_01` | Переключение на резервный канал связи (№23) |
| `replace_fan` | `solar_inverter_01` | Замена вентилятора инвертора (№31) |
| `set_workstation` (`IDLE` / `SOLDERING` / `HOT_AIR` / `OFF`) | `smart_panel_01` | Что делает Оператор на рабочем месте (реальный Оператор — отмечать вручную) |
| `remove_part` | `printer_3d_01` | Оператор снял деталь со стола |
| `set_door` | `thermal_insulation_01/02` | Открыл/закрыл дверь бокса |

Значение вводится как JSON (`{"fan": 0, "pwm": 200}`, `4`, `true`) или как строка (`RESERVE`).

**Линии щитка** (Обзор → «Умный щиток»): Вкл, Выкл, Взвести (сбросить сработавшую защиту),
Срабатывание (эмулировать срабатывание защиты — реальное реле выключится).

**Интерлоки** (Обзор → «Автоматика купола»): Блок (на N минут, до 30), Разблок, Снять
(перевзвести и вернуть отключённые им линии). «Вернуть доверие» — снять пометку
UNRELIABLE/FAILED с источника данных.

**Журнал автоматики**: «Квитировать» конкретное событие. **«Квитировать всё» отменяет и
автопуск пожаротушения** во всех зонах — при настоящем пожаре (К4) так делать нельзя.

### 3.6. Реальное устройство или симуляция

**Узлы → карточка → кнопка «→ real» / «→ virtual»** (есть у узлов с реальным устройством:
щиток, датчик климата, принтер, фрезер, инвертор и АКБ, теплицы). Бейдж в карточке —
текущий режим. «→ real» не сработает, если устройство недоступно — причина в «Журнале».
Узел, вручную переведённый в virtual, сервер сам обратно в real не переводит.

### 3.7. Время

**Пауза / Продолжить** — остановить и продолжить симуляцию. **Скорость ×N** — ускорение
симуляции (для отладки; во время смены не менять).

### 3.8. Права участника

**Доступ → «Загрузить политику»**, выбрать узел, вписать действия через запятую (или `*` —
все), галочка «Узел виден» → **«Сохранить для узла»**. Изменения сохраняются в
`authorization/access_policy.json` и действуют сразу. **«Перечитать файл»** — если файл правили
руками. Права админа не меняются.

## 4. Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Кнопка не сработала | Вкладка «Журнал» — текст ошибки сервера |
| Кризис ведёт себя не так | «Остановить» в «Активных кризисах»; подмены снимутся |
| Агент не может управлять устройством | Проверить режим узла (real/virtual), права в «Доступ», не заморожена ли линия (`lockout_remaining_s`), нет ли удержания станка (`hold_reason`) |
| Станок в ALARM от удержания (`hold_level = ALARM`) | Узлы → `release_hold` (снимает удержание; продолжить — `resume`) |
| Блэкаут: реле выключены | Обзор → Энергосистема: ошибка инвертора (E02/E04/E07); реле вернутся сами, когда шина под напряжением |
| Нужно начать заново | «Сбросить мир и начать смену» |

## 5. Ключи

Ключи — `Janus/data/Hash-keys` (`admin.txt`, `team_1..4.txt`), их SHA-256 — в
`authorization/keys_config.json`. Перегенерация (старые ключи перестают действовать):

```
cd Janus/server/authorization
python generate_keys.py --out ../../data/Hash-keys
```

Файлы ключей не коммитятся (`data/Hash-keys/.gitignore`).
