# Задание и критерии оценки

## Легенда

Купол выживальщика — автономная база: солнечные панели, аккумуляторы, дизель, щиток на 8
линий, вентиляция, вода, связь, мастерская с 3D-принтером и ЧПУ-фрезером, боксы МС-ТЮК.
Часть оборудования настоящая, часть — виртуальная, но для агента разницы нет: всё доступно
через один API ([01_API.md](01_API.md)).

В куполе работает **Оператор** — человек, который выполняет производственную задачу. Купол
живёт своей жизнью: датчики врут, оборудование ломается, автоматика срабатывает по ложным
данным, бывают и настоящие аварии. **Ваша задача — написать ИИ-агента, который следит за
куполом и делает так, чтобы работа Оператора не прерывалась.**

## Формат

**День 1 — подготовка.** Команды пишут агента. У каждой команды свой тренировочный купол —
полностью виртуальная копия с тем же API. Для подготовки есть:

- описание API — [01_API.md](01_API.md);
- недельный журнал купола — что происходило на прошлой неделе и как с этим справлялись
  (раздел 11 API), бортовой журнал жильцов;
- база знаний на сервере данных организаторов и ИИ-помощник по куполу.

**День 2 — смена.** Команды по очереди отправляют в купол одного участника — он становится
**Оператором** на 1,5 часа. Агент команды в это время управляет реальным куполом. Сценарий
смены одинаковый для всех команд: то же время старта, те же условия и те же нештатные ситуации.
По-разному они развиваются только из-за действий агента — в этом и состоит соревнование.

## Производственная задача Оператора

Задания Оператор пишет агенту в чат купола (`meeting_01`), например: напечатать корпус
устройства, отфрезеровать печатные платы, затем смонтировать и спаять их на рабочем месте.

- **Печать и фрезеровку запускает агент** (`start_job` по файлам, которые заранее загрузили
  организаторы). Пульта у принтера нет — Оператор не может сам запустить, продолжить или
  отменить печать.
- Поставить станок на паузу или снять задание агент не может: это делает только автоматика
  купола (раздел 7.1 API).
- Принтер стоит в закрытом боксе. Готовую деталь Оператор забирает, когда агент откроет замок.
- Пайка и монтаж — руками Оператора, на рабочем месте с вытяжкой.

## Что должен уметь агент

- **Держать производство в работе.** Запускать задания, следить за станками, возвращать их в
  работу после остановок — когда причина действительно устранена.
- **Отличать ложную тревогу от настоящей.** Один датчик против двух других, показание, которое
  противоречит физике, застывшие данные — признаки сбоя. Ложная тревога не должна
  останавливать работу, а настоящая — должна быть отработана.
- **Упреждать угрозы.** Многие проблемы видны заранее: энергия к вечеру, растущая утечка,
  деградация связи. Хороший агент действует до того, как проблема дойдёт до Оператора.
- **Беречь время Оператора.** Оператор — «руки» агента для физических действий (осмотреть
  кабель, почистить фильтр, переключить канал связи). Обращайтесь к нему, только когда без него
  не обойтись, и коротко: что сделать, где, зачем. Не просите подтвердить то, что видно по данным.
- **Проверять результат.** Ответ «принято» не значит «сделано» — результат команды виден только
  в телеметрии.
- **Расставлять приоритеты.** Бывают моменты, когда одновременно идут несколько событий.

## Критерии оценки

Оценка складывается из метрик, которые сервер считает автоматически за смену, и экспертной
оценки организаторов по логам агента и журналу смены.

| Критерий | Что смотрят |
|---|---|
| Непрерывность производства | Время простоя принтера, фрезера и рабочего места Оператора из-за нештатных ситуаций |
| Результат задачи | Сделаны ли корпус и платы, выполнен ли монтаж |
| Ложные тревоги | Сколько ложных тревог агент распознал, не остановив производство |
| Упреждение угроз | Сколько угроз агент отработал до того, как они перешли в последствия (обесточивание, остановка станков) |
| Время реакции | Как быстро агент начал действовать после начала события |
| Отвлечения Оператора | Число и уместность обращений к Оператору; лишние просьбы — минус |
| Ошибочные действия | Отключение исправного оборудования, блокировка настоящей тревоги, опасные сбросы защиты, продолжение работы без нужной подготовки |
| «Слепые» действия | Повторы команд без проверки результата, пустые попытки продолжить станок, частые переключения линий, блокировки оборудования из-за этого |
| Безопасность | Работа без вытяжки, духота (CO₂), обесточивание купола |
| Качество логов агента | Логи ведутся по формату ([03_Требования_к_агенту.md](03_Требования_к_агенту.md)), по ним понятно, что агент видел, что решил и почему |

Конкретные веса критериев определяют организаторы.

## Правила

- **Во время смены куполом управляет только агент.** Отправлять команды куполу вручную
  (людьми команды с ключом команды) нельзя.
- Агент работает на ключе DeepSeek, который выдают организаторы; другие облачные LLM
  запрещены (подробно — в требованиях).
- Ключ доступа к куполу — только для своей команды. Нельзя использовать чужие ключи, нагружать
  сервер запросами, пытаться обойти права доступа.
- Чат купола общий для всех команд: не мешайте чужой смене (не пишите Оператору другой команды,
  не засоряйте чат).
- Агент должен соответствовать [требованиям к агенту](03_Требования_к_агенту.md); логи агента
  за смену команда сдаёт организаторам сразу после смены.
- Нарушения правил — штраф или дисквалификация по решению организаторов.
