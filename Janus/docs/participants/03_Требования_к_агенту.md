# Требования к агенту

Агент работает **на ноутбуке команды** и подключается к серверу купола по сети организаторов.
В день 2 вы переключаете его с тренировочного купола на реальный — меняется только адрес
сервера. Проверьте всё заранее на тренировочном куполе (день 1): любая заминка со
стартом агента на смене — простой вашего производства.

## 1. Запуск

- Агент запускается **одной командой** (например, `python main.py`) и дальше работает
  **без участия человека**: никакого ввода с клавиатуры, окон, подтверждений. Ручные команды
  куполу во время смены запрещены ([правила](02_Задание_и_оценка.md#правила)).
- Язык и стек — на ваш выбор. Для Python опишите зависимости в `requirements.txt`, чтобы
  агента можно было поднять на чистой машине.
- Агент должен **переживать собственный перезапуск**: если он упал или вы его перезапустили,
  он сам подключается и восстанавливает картину по телеметрии (если нужно — сохраняет
  состояние в файл). Не рассчитывайте, что память процесса переживёт перезапуск.
- При остановке (Ctrl+C, `SIGTERM`) агент закрывает логи — после него должен остаться
  полный лог.
- Код агента храните в репозитории (git). После смены организаторы могут попросить показать
  код и версию, с которой работал агент.

## 2. Конфигурация

Всё, что отличается между тренировочным и реальным куполом, — только через переменные
окружения. Ключи **не храните в репозитории** (добавьте `.env` в `.gitignore`, положите в
репозиторий `.env.example` без значений).

| Переменная | Что это | Пример |
|---|---|---|
| `DOME_URL` | Адрес сервера купола | `ws://192.168.8.10:8765` |
| `DOME_KEY` | Ключ доступа команды | выдают организаторы |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek | выдают организаторы |
| `DEEPSEEK_BASE_URL` | Адрес API DeepSeek (необязательно) | `https://api.deepseek.com` |
| `AGENT_LOG_DIR` | Каталог логов агента (раздел 5) | по умолчанию `logs` |

Свои дополнительные переменные можно добавлять — с разумными значениями по умолчанию.

## 3. Языковая модель

- Облачная LLM — **только DeepSeek** с ключом, который выдали организаторы. Другие облачные
  LLM и API (OpenAI, Anthropic, Google и т. д.) использовать нельзя.
- API DeepSeek совместим с OpenAI: подойдёт пакет `openai` с `base_url`. Названия моделей —
  по списку организаторов (на момент написания — `deepseek-chat` и `deepseek-reasoner`).

  ```python
  import os
  from openai import OpenAI

  llm = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
               base_url=os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com"))
  resp = llm.chat.completions.create(
      model="deepseek-chat",
      messages=[{"role": "system", "content": "Ты — агент купола..."},
                {"role": "user", "content": "Телеметрия: ..."}],
      timeout=30)
  print(resp.choices[0].message.content, resp.usage.prompt_tokens, resp.usage.completion_tokens)
  ```
- **Локальные модели разрешены** — эмбеддинги для RAG, небольшие классификаторы и т. п. — на
  вашем ноутбуке. Скачайте веса заранее: на смене не рассчитывайте на доступ в интернет, кроме
  API DeepSeek.
- Ответ LLM приходит за секунды, а иногда не приходит вовсе (таймаут, ошибка, лимит).
  **Агент должен продолжать работать без LLM**: проверка безопасности, повторные запросы с
  паузой, простые правила на случай недоступности модели. Не ждите ответа модели там, где
  нужно реагировать сразу.
- Ключ DeepSeek выдаётся с ограниченным бюджетом: не отправляйте модели всю телеметрию каждые
  2 секунды — выбирайте, что и когда спрашивать.

## 4. Поведение

- **Переподключение.** При разрыве соединения, ошибке сети или `session_revoked` агент
  переподключается сам (с паузой, не чаще раза в несколько секунд).
- **Роль гостя.** Вне своей смены агент получает роль `guest` (только чат) — это нормально:
  агент не должен падать, а ждать своей смены и переподключаться.
- **Устойчивость к данным.** Любое показание может быть `null`, узел может пропасть из
  телеметрии, команда — вернуть ошибку. Агент не должен падать из-за этого.
- **Не перегружайте сервер:** не больше 5 команд и запросов в секунду, в чат — не больше
  10 сообщений за 10 секунд (иначе сервер отклонит), не повторяйте одну и ту же команду
  подряд без проверки результата.
- **Права.** Используйте только свой ключ и разрешённые действия (`describe_nodes`). Попытки
  обойти права доступа — нарушение правил.

## 5. Логи агента

Агент обязан вести лог своей работы. По нему организаторы проверяют соблюдение правил и
оценивают, **что агент видел, что решил и почему**. Лог входит в критерии оценки.

### Файлы

- Каталог — `AGENT_LOG_DIR` (по умолчанию `logs` рядом с агентом). **Сразу после смены
  передайте организаторам все файлы логов за смену** (как именно — скажут организаторы).
  Нет лога — нет оценки по этому критерию.
- Новый файл на каждый запуск: `agent_<run_id>.jsonl`, где `run_id` — время запуска,
  например `20261024-133005`.
- Формат — **JSON Lines**, кодировка UTF-8: одна строка — один JSON-объект. Пишите построчно и
  сразу сбрасывайте на диск (`flush`) — после падения лог должен остаться.
- **Никаких ключей в логах** (ни `DOME_KEY`, ни `DEEPSEEK_API_KEY`).
- Не пишите в лог всю телеметрию каждые 2 секунды — для этого есть журнал купола на сервере.

### Общие поля каждой записи

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `ts` | строка | да | Время записи, ISO 8601 с миллисекундами и часовым поясом: `2026-10-24T13:30:05.123+03:00` |
| `run_id` | строка | да | Идентификатор запуска (как в имени файла) |
| `seq` | число | да | Номер записи в файле: 1, 2, 3… |
| `kind` | строка | да | Тип записи (таблица ниже) |
| `dome_time` | строка | нет | Часы купола `HH:MM` из `game_time` телеметрии |
| `ref` | число | нет | `seq` записи, к которой относится эта (решение → действие → проверка) |

### Типы записей

| `kind` | Когда | Поля |
|---|---|---|
| `start` | Запуск агента | `agent` — название, `version` — коммит или версия, `models` — список моделей, `config` — настройки **без ключей** (`dome_url`, …) |
| `stop` | Штатная остановка | `reason` |
| `connection` | Подключение, авторизация, разрыв, переподключение | `event`: `connected` \| `auth` \| `disconnected` \| `revoked`; `role`, `team` (после `auth`); `details` |
| `observation` | Сводка состояния: раз в 30–60 с и при заметных изменениях | `summary` — кратко текстом; `metrics` — ключевые показатели, за которыми следит агент (`{"soc_pct": 64, "printer": "PRINTING", ...}`); `anomalies` — что агент считает необычным |
| `decision` | Агент решил, что делать (или не делать) | `situation` — что происходит, по мнению агента; `cause` — предполагаемая причина; `confidence` — 0..1; `evidence` — на что опирается (`[{"node": "climate_sensor_02", "param": "co2_ppm", "value": 780}, ...]`); `plan` — что будет делать; `source`: `rules` \| `llm` \| `rag` \| `mixed`; `rag_refs` — какие записи базы знаний использованы (необязательно) |
| `action` | Каждая команда или запрос к серверу купола | `request` — отправленный JSON (`type`, `node_id`, `action`/`query`, `value`/`params`); `response` — `success` и `error`; `ref` — решение, из которого выросла команда |
| `verification` | Проверка результата команды по телеметрии | `ref` — запись `action`; `expected`; `observed`; `ok` — `true`/`false` |
| `message` | Сообщение в чате купола — отправленное или полученное | `direction`: `out` \| `in`; `to` / `sender`; `text` |
| `llm_call` | Каждый вызов языковой модели | `model`; `purpose` — зачем вызов; `prompt_tokens`, `completion_tokens`; `latency_ms`; `ok`; `error`; `summary` — суть ответа; необязательно `prompt`, `response` (полный текст, можно обрезать до 4000 символов) |
| `error` | Исключения и сбои агента | `where`, `error`, `traceback` (необязательно) |

Правила связи записей:

- у каждой записи `action` есть `ref` на `decision` (у рутинных действий — тоже: решение может
  быть коротким, `source: "rules"`);
- после команды, которая меняет состояние купола, — запись `verification`;
- каждое сообщение Оператору — запись `message` с `direction: "out"`.

Свои поля добавлять можно — к обязательным.

### Минимальная реализация

```python
import json, os
from datetime import datetime


class AgentLog:
    def __init__(self):
        folder = os.getenv("AGENT_LOG_DIR", "logs")
        os.makedirs(folder, exist_ok=True)
        self.run_id = datetime.now().strftime("%Y%m%d-%H%M%S")
        self.file = open(os.path.join(folder, f"agent_{self.run_id}.jsonl"), "a",
                         encoding="utf-8", buffering=1)   # построчная запись
        self.seq = 0

    def write(self, kind, **fields):
        self.seq += 1
        record = {"ts": datetime.now().astimezone().isoformat(timespec="milliseconds"),
                  "run_id": self.run_id, "seq": self.seq, "kind": kind, **fields}
        self.file.write(json.dumps(record, ensure_ascii=False, default=str) + "\n")
        return self.seq   # чтобы ссылаться на запись через ref


log = AgentLog()
d = log.write("decision", situation="...", cause="...", confidence=0.8, evidence=[], plan=[], source="rules")
log.write("action", request={"type": "control", "node_id": "cnc_01", "action": "resume"},
          response={"success": True}, ref=d)
```

## 6. Рекомендации

- **`README.md` в репозитории** — коротко: как устроен агент, какие модули, как запустить
  локально. Это помогает организаторам разобраться в логах и спорных ситуациях.
- **Разделите правила и модель.** Проверки безопасности и простые реакции (не делать `resume`,
  пока причина не ушла; проверять результат команды) — обычным кодом; LLM — для диагностики,
  сопоставления с историей и формулировки сообщений Оператору.
- **Режим «только наблюдение»** (переменная вроде `AGENT_DRY_RUN=1`): агент всё анализирует и
  пишет в лог, но не отправляет команды. Удобно для отладки.
- **Тренируйтесь на тренировочном куполе**: проверьте запуск с чистого клона репозитория,
  переподключение, работу при недоступной LLM.
